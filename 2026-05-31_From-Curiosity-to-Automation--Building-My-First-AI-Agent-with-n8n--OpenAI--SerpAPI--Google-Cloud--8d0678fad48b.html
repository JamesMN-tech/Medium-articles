From Curiosity to Automation: Building My First AI Agent with n8n, OpenAI, SerpAPI, Google Cloud, and Gmail

For years, I’ve worked in IT operations, systems administration, automation, and infrastructure. Like many IT professionals, I’ve watched the rapid rise of AI and wondered:

“How difficult would it be to build my own AI-powered automation?”

Recently, I decided to stop wondering and start building.

The goal was simple:

Create an AI agent that automatically generates a weekly market summary and emails it to me every week without any manual intervention.

What followed was a fascinating journey through APIs, OAuth authentication, AI models, Google Cloud projects, email automation, and more troubleshooting than I care to admit.

This is the story of how I built my first successful AI workflow.

The Vision

I wanted a workflow that could:

  • Run automatically every week
  • Use AI to create a market summary
  • Search the web for information
  • Remember previous interactions
  • Format the output professionally
  • Deliver the report via Gmail

The finished workflow looked like this:

Schedule Trigger
      ↓
AI Agent
      ↓
OpenAI Model
      ↓
Memory
      ↓
Google Search (SerpAPI)
      ↓
Markdown to HTML
      ↓
Gmail

Simple when completed.

Not so simple getting there.

The Technology Stack

To make this project work, I needed several services.

n8n

The automation platform acting as the workflow engine.

OpenAI API

Provides the AI intelligence.

SerpAPI

Allows the AI to perform Google searches.

Google Cloud Platform

Used to create OAuth credentials for Gmail integration.

Gmail

Used to deliver the final market report.

The First Investment: OpenAI

One of the first lessons I learned was that ChatGPT and the OpenAI API are two different services.

ChatGPT Subscription

My ChatGPT subscription gives me access to ChatGPT itself.

However, it does not provide API access for applications such as n8n.

To connect n8n to OpenAI, I needed separate API credits.

Purchasing OpenAI API Credits

I logged into the OpenAI Platform billing portal and added funds.

As shown in my billing dashboard, I currently maintain:

OpenAI API Credit Balance: $20.00

This balance is used whenever n8n sends requests to OpenAI.

Every time my workflow runs, a small amount is deducted depending on:

  • Model selected
  • Number of tokens processed
  • Size of prompts
  • Frequency of execution

For my use case, a $20 balance will support many thousands of automated summaries.

Creating My First OpenAI API Key

After funding the account, I generated an API key.

Inside n8n:

Credentials
    ↓
OpenAI
    ↓
API Key

Once connected, the AI Agent could finally communicate with OpenAI.

That was the first major milestone.

Building the Workflow

I started with the Schedule Trigger.

Since I wanted a weekly report, I configured:

Schedule Trigger

to run automatically every Sunday morning.

This eliminated the need to manually start the process.

Creating the AI Agent

Next came the AI Agent.

This became the “brain” of the workflow.

I connected the AI Agent to the OpenAI Chat Model.

For the model, I selected:

GPT-4.1 Mini

because it provides:

  • Excellent quality
  • Fast responses
  • Very low API cost

Teaching the AI What to Do

The first prompt was straightforward:

You are a weekly market brief agent. Summarize the S&P 500 and provide a quote of the week.

Initially, I thought that was enough.

I was wrong.

The AI confidently generated market commentary even when no market data was supplied.

That taught me an important lesson:

AI can sound authoritative even when it doesn’t actually have the information.

I eventually rewrote the prompt to explicitly state:

Only use information supplied in the input. Do not invent facts.

The quality improved immediately.

Adding Memory

The next challenge was memory.

I wanted the AI Agent to remember previous interactions.

So I added:

Simple Memory

Unfortunately, the workflow immediately failed.

My First Major Error

The error message read:

Key parameter is empty

After a lot of testing, I discovered that memory requires a Session ID.

Since my workflow used a Schedule Trigger rather than a Chat Trigger, no session ID existed.

The solution was simple:

Instead of using a chat session, I created a static identifier:

weekly-market-session

Problem solved.

Memory successfully connected.

Purchasing SerpAPI

The AI still lacked access to live information.

I needed Google Search capability.

This is where SerpAPI came in.

I created a SerpAPI account and selected a plan suitable for testing and development.

The SerpAPI dashboard provides:

  • API Key
  • Search metrics
  • Billing information
  • Usage tracking

Once connected, the AI Agent could access Google Search results directly.

This dramatically expanded the agent’s capabilities.

Connecting SerpAPI to the AI Agent

Within n8n:

AI Agent
      ↓
Tool
      ↓
Google Search (SerpAPI)

The AI could now perform searches before generating responses.

At this point the workflow started feeling less like a chatbot and more like a genuine AI assistant.

Setting Up Google Cloud

Connecting Gmail turned out to be one of the most educational parts of the project.

To allow n8n to send emails on my behalf, I needed a Google Cloud Project.

Creating the Google Cloud Project

Inside Google Cloud Console I created:

N8N Project

The project became the foundation for OAuth authentication.

Configuring OAuth

Google requires applications to authenticate using OAuth.

Inside the project I configured:

Branding

Application name and branding information.

Audience

Testing users.

OAuth Consent Screen

Permissions requested from Gmail.

Clients

Generated:

  • Client ID
  • Client Secret

These credentials were later used inside n8n.

Connecting Gmail

Once OAuth was configured:

Credentials
     ↓
Gmail

I entered:

  • Client ID
  • Client Secret

Then authenticated my Gmail account.

After successful authentication, n8n could send emails automatically.

The Formatting Disaster

The workflow finally ran.

An email arrived.

And it looked terrible.

Instead of formatted content, I saw:

# Market Note
## Most Important Market News
\n\n

everywhere.

The content was correct.

The formatting was awful.

Understanding the Problem

The AI was generating Markdown.

Gmail expected HTML.

The two formats are not the same.

The Markdown Solution

I added a Markdown node:

Markdown

and configured:

Markdown → HTML

This converted AI-generated Markdown into proper HTML.

Another Mapping Problem

At one point the email literally contained:

{{ $json.output }}

instead of the actual content.

The cause?

The expression wasn’t being evaluated.

The fix?

Use expression mode correctly and map the correct field.

Eventually I learned one of the most important automation lessons:

Most workflow problems are not AI problems.
They are data mapping problems.

The Moment Everything Worked

After multiple tests, corrections, and troubleshooting sessions, I clicked:

Execute Workflow

A few seconds later an email arrived.

This time it was different.

The report contained:

  • Proper headings
  • Sections
  • Formatting
  • Quotes
  • Actionable takeaway

Everything looked professional.

The workflow had finally succeeded.

Lessons Learned

This project taught me far more than expected.

Lesson 1

AI is only as good as the data it receives.

Lesson 2

Memory requires session management.

Lesson 3

APIs are easier than they initially appear.

Lesson 4

OAuth is confusing the first time, but manageable.

Lesson 5

Most automation failures happen between nodes.

Lesson 6

Always test one node at a time.

Lesson 7

Small wins build confidence quickly.
